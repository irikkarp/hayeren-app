# Подготовка сервера Vultr для фичи 003 (инструкция для владельца)

Скрипты лежат в `server/ops/`. Вы запускаете их сами; агенты доступа к серверу не получают (решение 2026-10-24). Пока на сервере нет кода бэкенда: мы только готовим безопасную основу и проверяем, что работает HTTPS.

Если что-то непонятно или вывод выглядит странно, остановитесь и пришлите его в чат. Спешить некуда, все шаги можно повторять.

## Правила безопасности (коротко)

- Пароль root из панели Vultr, приватный ключ (файл БЕЗ `.pub`) и токен бота в чат не присылаем никогда.
- Присылать можно: вывод `00-check.sh`, IP сервера, username бота, публичный ключ (файл `.pub`).
- Токен бота живёт только в `/opt/hayeren/.env` на сервере.
- Не закрывайте рабочее окно Терминала, пока не проверите новый вход в отдельном окне.

## Что нужно до начала

- Сервер Vultr с Ubuntu 24.04 или 26.04 (у вас 26.04; на другой системе скрипты спросят подтверждение).
- IP-адрес сервера и пароль root в панели Vultr (my.vultr.com, Products, ваш сервер, Overview).
- Ссылка на репозиторий: https://github.com/irikkarp/hayeren-app (публичный).

## Шаг 0. Создайте SSH-ключ на Mac

SSH-ключ это пара файлов: приватный (секрет, остаётся на Mac) и публичный (его кладём на сервер). Откройте Терминал (Cmd+Пробел, "Терминал") и выполните:

```
ssh-keygen -t ed25519 -C "hayeren" -f ~/.ssh/hayeren_vultr
```

Придумайте парольную фразу (при вводе символы не видны, это нормально) и сохраните её в менеджере паролей. Появятся два файла:

- `~/.ssh/hayeren_vultr` приватный, никому не показывать;
- `~/.ssh/hayeren_vultr.pub` публичный. Показать его: `cat ~/.ssh/hayeren_vultr.pub` (одна строка, начинается с `ssh-ed25519`). Он понадобится на шаге 2.

## Шаг 1. Подключитесь к серверу и получите скрипты

Подключение (замените `IP` на адрес сервера; на вопрос про fingerprint ответьте `yes`):

```
ssh root@IP
```

Введите пароль из панели Vultr (символы не отображаются; можно вставить Cmd+V). Появится приглашение вида `root@имя:~#`: вы на сервере.

Получить скрипты, вариант А (проще), на сервере:

```
apt-get update && apt-get install -y git
git clone https://github.com/irikkarp/hayeren-app.git /root/hayeren-app
cd /root/hayeren-app/server/ops
```

Вариант Б: с Mac, если репозиторий уже скачан (в новом окне Терминала на Mac, из папки проекта):

```
scp -r server/ops root@IP:/root/ops
```

и на сервере `cd /root/ops`.

Вариант А работает только после того, как папка `server/ops` закоммичена и отправлена в GitHub (main). Пока этого нет, используйте вариант Б.

Проверьте, что вы в нужной папке: `ls` должен показать `00-check.sh`, `10-user-and-ssh.sh` и другие.

## Шаг 2. Осмотр сервера (ничего не меняет)

```

```

Скопируйте весь вывод и пришлите в чат. В нём нет паролей и ключей, есть только версии, ресурсы и открытые порты. Мы проверим, что сервер пустой (порты 80/443 свободны, нет nginx/Docker), и скажем, можно ли идти дальше.

Если на сервере уже есть сайты или сервисы, дальше не идите, ждите нашего ответа.

## Особенности вашего сервера (читать первым)

На сервере уже работает ваш VPN (Amnezia, контейнер `amnezia-awg2`). Hayeren живёт рядом с ним, поэтому скрипты адаптированы так, чтобы VPN не пострадал:

| Что | Решение | Почему |
|---|---|---|
| Вход root и вход по паролю | НЕ отключаем | Приложение Amnezia заходит по SSH под root; запрет оборвал бы управление VPN |
| Docker | Не переустанавливаем, демон НЕ перезапускаем, `daemon.json` не трогаем | Перезапуск демона остановит VPN-контейнер. Ротация логов задана в compose-файлах |
| ufw | Только добавляем 80/tcp, 443/tcp, 443/udp | Политики, reset, reload и существующие правила не трогаем. Порт VPN в ufw не открыт (Docker публикует его мимо ufw), так и оставляем |
| fail2ban | Ставим для SSH, бан 10 минут | Использует свою цепочку только для порта SSH, правила Docker/VPN не затрагивает |
| Swap, автообновления | Уже есть, пропускаем | Автоперезагрузку не включаем: перезагрузка уронит VPN |
| Память | Caddy `mem_limit` 128 МБ, будущий API 256 МБ | Всего 950 МБ RAM на всё; потолки не дают нашим сервисам вытеснить VPN |

Шаги 0-2 вы уже выполнили (ключ `~/.ssh/hayeren_vultr` создан, репозиторий склонирован в `/root/hayeren-app`, осмотр сделан). Дальше идём с шага 3. После каждого шага присылайте в чат то, что указано в строке "Прислать".

Перед скриптами, которые что-то меняют (3-6), скрипты печатают состояние VPN-контейнера и после работы сравнивают его с исходным. Если вы увидите "СОСТОЯНИЕ VPN-КОНТЕЙНЕРА ИЗМЕНИЛОСЬ", проверьте VPN в приложении и напишите нам.

## Шаг 3. Пользователь deploy и ключ (следующий шаг для вас)

Создаём второго пользователя `deploy` для деплоев Hayeren. Настройки SSH не меняются, приложение Amnezia продолжает работать как раньше.

3.1. Подключитесь к серверу как обычно (`ssh root@208.85.20.164` или как вы входили раньше) и выполните:

```
cd /root/hayeren-app && git pull
cd server/ops
bash 10-user-and-ssh.sh prepare
```

Скрипт попросит придумать пароль для `deploy` (нужен только для `sudo`) и вставить публичный ключ. На Mac в другом окне получите его командой `cat ~/.ssh/hayeren_vultr.pub` и вставьте строку целиком. Приватный ключ скрипт не примет.

`git pull` нужен, чтобы получить обновлённые скрипты (в старой версии на сервере был режим `harden`, который запрещает root и пароли: его запускать НЕЛЬЗЯ, он сломает Amnezia). Мы сообщим, когда обновление отправлено в GitHub; до этого шаг 3 не начинайте. Запасной вариант с Mac из папки проекта: `scp -r server/ops root@208.85.20.164:/root/ops-new`, затем на сервере `cd /root/ops-new`.

Если `git pull` ругается на локальные изменения, не исправляйте сами, пришлите текст в чат.

3.2. В НОВОМ окне Терминала на Mac проверьте вход:

```
ssh -i ~/.ssh/hayeren_vultr deploy@208.85.20.164
```

Должен спросить парольную фразу ключа и пустить: `deploy@имя:~$`. Если не пустил, пришлите текст ошибки (`ssh -v -i ~/.ssh/hayeren_vultr deploy@208.85.20.164` даёт подробности).

Прислать: "шаг 3 готов, вход deploy по ключу работает" (или текст ошибки). Паролей и ключей присылать не нужно.

## Шаг 4. Фаервол и fail2ban

Запускать под root (или `sudo` под deploy):

```
cd /root/hayeren-app/server/ops
bash 20-firewall.sh
```

Скрипт откроет только 80/tcp, 443/tcp, 443/udp (политики и существующие правила не меняются), сохранит копию текущих правил в `/root/fw-backup-...`, поставит fail2ban. Он спросит, добавить ли ваш текущий IP в белый список fail2ban: ответьте `y`, если у вас стабильный домашний IP (иначе позже: `bash 20-firewall.sh <IP>`).

Важно про fail2ban и Amnezia: если вы ошибётесь паролем в приложении Amnezia 5 раз за 10 минут, ваш IP заблокируется на 10 минут (только для SSH, сам VPN продолжит работать). Разбан раньше срока: веб-консоль Vultr (my.vultr.com, сервер, View Console), войти root:

```
fail2ban-client status sshd
fail2ban-client set sshd unbanip ВАШ_IP
```

Прислать: вывод скрипта целиком. Откат ufw-правил: `ufw delete allow 80/tcp` (и так же для 443/tcp, 443/udp). Отключить fail2ban: `systemctl disable --now fail2ban`. Ничего из этого VPN не задевает.

## Шаг 5. Docker Compose (Docker не переустанавливается)

```
bash 30-docker.sh
```

Скрипт только проверяет `docker compose version`. Если плагина нет, он сначала делает симуляцию установки пакета `docker-compose-v2` и останавливается, если apt захочет обновить Docker, containerd или runc. Демон не перезапускается, `daemon.json` не меняется. Отдельно спросит про добавление deploy в группу docker (эквивалентно правам root; для наших деплоев рекомендуем "да"). После этого deploy нужно перезайти по SSH.

Прислать: вывод скрипта целиком.

## Шаг 8. Проверка HTTPS

```
bash 60-https-check.sh
```

Адрес по умолчанию: `208-85-20-164.sslip.io` (просто нажмите Enter). Скрипт сначала проверяет, что 80/443 свободны и их не использует VPN, и при конфликте останавливается, ничего не запуская. Затем запускает ТОЛЬКО контейнер Caddy (лимит памяти 128 МБ) и получает бесплатный сертификат. Откройте `https://208-85-20-164.sslip.io/health` в браузере: замок и слово `ok`. После запуска скрипт сравнивает состояние VPN-контейнера с исходным.

VPN работает на собственном порту (UDP/TCP, выбранном Amnezia), не на 80/443, поэтому Caddy ему не мешает. Если окажется иначе, скрипт остановится на проверке портов.

Остановить тест: `bash 60-https-check.sh down` (останавливается только Caddy). Не запускайте `up` много раз подряд: у Let's Encrypt есть лимиты. Прислать: результат и, при ошибке, логи, которые покажет скрипт.

## Память: 950 МБ на всё

Грубо: система, Docker и VPN-контейнер занимают 250-400 МБ, Caddy до 128 МБ, будущий API до 256 МБ (потолки заданы в `server/ops/templates/docker-compose.*.yml`), SQLite живёт внутри процесса API. Швы закрывает swap 2,3 ГБ, но он медленный, и при нехватке памяти ядро может убить процесс, в том числе VPN. Поэтому после запуска Caddy, а затем API присылайте нам `free -m` и `docker stats --no-stream`. Если свободной памяти (available) стабильно меньше 150 МБ, поднимите тариф Vultr до 2 ГБ (Change Plan; обычно требует кратковременной перезагрузки, выбирайте удобное время и предупредите пользователей VPN).

## Необязательно: перевод Amnezia на вход по ключу и отключение паролей

Делать позже и только по желанию. Сейчас этот шаг не нужен и скриптами не автоматизирован, потому что можно потерять управление VPN.

1. В приложении Amnezia сервер подключается по SSH. В настройках сервера (при добавлении или повторном подключении) выберите вход по SSH-ключу и вставьте приватный ключ, который на сервере разрешён для root. Проверьте, что приложение реально подключилось (например, откройте список клиентов VPN). Надёжнее создать для Amnezia отдельный ключ (`ssh-keygen -t ed25519 -f ~/.ssh/amnezia_vultr`) и добавить его `.pub` в `/root/.ssh/authorized_keys`.
2. Проверьте вход root по ключу вручную из нового окна: `ssh -i ~/.ssh/amnezia_vultr root@208.85.20.164`.
3. Только после этого, не закрывая рабочее окно, создайте файл `/etc/ssh/sshd_config.d/00-hayeren.conf` с содержимым `PasswordAuthentication no` и `KbdInteractiveAuthentication no` (root-вход по ключу остаётся: он нужен Amnezia), проверьте `sshd -t` и выполните `systemctl reload ssh`. Проверьте вход и приложение Amnezia.
4. Откат: удалить этот файл и `systemctl reload ssh`. Если потеряли доступ: веб-консоль Vultr.

Просите нас подготовить точные команды, когда будете готовы.

## Шаг 9. Бот в Telegram и токен

Сначала мы согласуем с вами, когда это делать (токен нужен, когда будет готов бэкенд); бота можно создать заранее.

1. В Telegram откройте @BotFather (официальный бот с галочкой), отправьте `/newbot`.
2. Введите отображаемое имя (например, "Hayeren") и username, заканчивающийся на `bot` (например, `hayeren_app_bot`). Имя публичное, менять неудобно.
3. BotFather пришлёт токен вида `123456789:AAH...`. Это пароль от бота. Не пересылайте его никому, не вставляйте в чат с нами, не коммитьте. Сохраните в менеджере паролей.
4. На сервере (под deploy):

```
sudo bash ~/hayeren-app/server/ops/55-set-bot-token.sh   # или /root/hayeren-app/... под root
```

Скрипт попросит токен (ввод скрыт, на экране ничего не появляется) и username бота, запишет в `/opt/hayeren/.env` с правами 600. Токен нигде не печатается.
5. Нам пришлите только username бота (он публичный).
6. Если токен случайно попал куда-то лишнее: в @BotFather `/revoke`, затем повторите пункт 4 с новым токеном.

## Что делать, если потеряли доступ

1. Веб-консоль Vultr: my.vultr.com, ваш сервер, значок "View Console" (экран) вверху. Это вход как "физический" монитор, он работает без SSH и фаервола.
2. В консоли войдите как root или как `deploy` (пароль, который вы задавали).
3. Если IP забанен fail2ban: `fail2ban-client set sshd unbanip ВАШ_IP`.
4. Если сломалось правило фаервола: удалите только наше правило (`ufw status numbered`, затем `ufw delete НОМЕР` для 80/443). Не делайте `ufw disable` и `ufw reset` без согласования: на сервере работает VPN.
5. Переустановка сервера в панели Vultr уничтожит VPN и все данные. Не делайте этого, не посоветовавшись с нами.
6. Забыли парольную фразу ключа: создайте новый ключ (шаг 0 с другим именем файла) и добавьте его через консоль Vultr в `/home/deploy/.ssh/authorized_keys`.
7. Не перезапускайте Docker (`systemctl restart docker`) и не перезагружайте сервер без необходимости: VPN остановится. Docker-контейнеры с `restart: unless-stopped` поднимутся сами после перезагрузки сервера.

Если при входе пишет `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED`, это может быть переустановка сервера. Если вы её делали, удалите старую запись: `ssh-keygen -R IP`. Если не делали, не входите и сообщите нам.
