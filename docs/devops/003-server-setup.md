# Подготовка сервера Vultr для фичи 003 (инструкция для владельца)

Скрипты лежат в `server/ops/`. Вы запускаете их сами; агенты доступа к серверу не получают (решение 2026-10-24). Пока на сервере нет кода бэкенда: мы только готовим безопасную основу и проверяем, что работает HTTPS.

Если что-то непонятно или вывод выглядит странно, остановитесь и пришлите его в чат. Спешить некуда, все шаги можно повторять.

## Правила безопасности (коротко)

- Пароль root из панели Vultr, приватный ключ (файл БЕЗ `.pub`) и токен бота в чат не присылаем никогда.
- Присылать можно: вывод `00-check.sh`, IP сервера, username бота, публичный ключ (файл `.pub`).
- Токен бота живёт только в `/opt/hayeren/.env` на сервере.
- Пока вы не закончили шаг 2, не закрывайте окно Терминала, в котором вы вошли как root.

## Что нужно до начала

- Сервер Vultr с Ubuntu 24.04 (если у вас другая система, скажите, это нормально, но скрипты спросят подтверждение).
- IP-адрес сервера и пароль root в панели Vultr (my.vultr.com, Products, ваш сервер, Overview).
- Ссылка на репозиторий: https://github.com/irikkarp/hayeren-app (публичный).

## Шаг 0. Создайте SSH-ключ на Mac

SSH-ключ это пара файлов: приватный (секрет, остаётся на Mac) и публичный (его кладём на сервер). Откройте Терминал (Cmd+Пробел, "Терминал") и выполните:

```
ssh-keygen -t ed25519 -C "hayeren" -f ~/.ssh/hayeren_vultr
```

Придумайте парольную фразу (при вводе символы не видны, это нормально) и сохраните её в менеджере паролей. Появятся два файла:

- `~/.ssh/hayeren_vultr` приватный, никому не показывать;
- `~/.ssh/hayeren_vultr.pub` публичный. Показать его: `cat ~/.ssh/hayeren_vultr.pub` (одна строка, начинается с `ssh-ed25519`). Он понадобится на шаге 2.

## Шаг 1. Подключитесь к серверу и получите скрипты

Подключение (замените `IP` на адрес сервера; на вопрос про fingerprint ответьте `yes`):

```
ssh root@IP
```

Введите пароль из панели Vultr (символы не отображаются; можно вставить Cmd+V). Появится приглашение вида `root@имя:~#`: вы на сервере.

Получить скрипты, вариант А (проще), на сервере:

```
apt-get update && apt-get install -y git
git clone https://github.com/irikkarp/hayeren-app.git /root/hayeren-app
cd /root/hayeren-app/server/ops
```

Вариант Б: с Mac, если репозиторий уже скачан (в новом окне Терминала на Mac, из папки проекта):

```
scp -r server/ops root@IP:/root/ops
```

и на сервере `cd /root/ops`.

Вариант А работает только после того, как папка `server/ops` закоммичена и отправлена в GitHub (main). Пока этого нет, используйте вариант Б.

Проверьте, что вы в нужной папке: `ls` должен показать `00-check.sh`, `10-user-and-ssh.sh` и другие.

## Шаг 2. Осмотр сервера (ничего не меняет)

```
bash 00-check.sh
```

Скопируйте весь вывод и пришлите в чат. В нём нет паролей и ключей, есть только версии, ресурсы и открытые порты. Мы проверим, что сервер пустой (порты 80/443 свободны, нет nginx/Docker), и скажем, можно ли идти дальше.

Если на сервере уже есть сайты или сервисы, дальше не идите, ждите нашего ответа.

## Шаг 3. Пользователь deploy и вход по ключу (самый важный шаг)

Идея: сначала создаём второй вход (пользователь `deploy` с ключом), проверяем его, и только потом запрещаем пароль и root. Так вы не окажетесь за закрытой дверью.

3.1. На сервере (окно А, вы root):

```
bash 10-user-and-ssh.sh prepare
```

Скрипт попросит придумать пароль для `deploy` (нужен только для команды `sudo`; по SSH пароли будут запрещены) и вставить публичный ключ: вставьте строку из `cat ~/.ssh/hayeren_vultr.pub`. Приватный ключ скрипт не примет и скажет об этом.

3.2. Откройте НОВОЕ окно Терминала на Mac (окно А не закрывайте!):

```
ssh -i ~/.ssh/hayeren_vultr deploy@IP
```

Должен запросить парольную фразу ключа (не пароль сервера) и пустить вас: `deploy@имя:~$`. Если не пустил, останавливайтесь, ничего дальше не запускайте, пришлите текст ошибки (`ssh -v` даёт подробности).

3.3. Вернитесь в окно А и запретите пароли и root:

```
bash 10-user-and-ssh.sh harden
```

Скрипт сам проверит в журнале, что вход deploy по ключу уже был, и спросит подтверждение. После этого проверьте вход ещё раз из третьего окна (команда из 3.2).

Откат этого шага (если новый вход перестал работать, а окно А ещё открыто):

```
bash 10-user-and-ssh.sh rollback
```

С этого момента работаем в окне под `deploy`, а команды с правами root пишем через `sudo` (пароль: тот, что вы задали для deploy). Скрипты тоже копируем себе:

```
git clone https://github.com/irikkarp/hayeren-app.git ~/hayeren-app
cd ~/hayeren-app/server/ops
```

(или `scp -r server/ops deploy@IP:~/ops`, для scp добавьте `-i ~/.ssh/hayeren_vultr`).

Пришлите в чат: "шаг 3 готов, вход deploy по ключу работает" (больше ничего не нужно).

## Шаг 4. Фаервол и fail2ban

```
sudo bash 20-firewall.sh
```

Открыты будут только 22 (SSH), 80 и 443. Порт 22 скрипт разрешает до включения фаервола, соединение не оборвётся. Прислать: вывод `ufw status` из конца скрипта.

Откат: `sudo ufw disable`.

## Шаг 5. Docker

```
sudo bash 30-docker.sh
```

Скрипт спросит подтверждение и отдельно спросит про добавление deploy в группу docker (это эквивалентно правам root, но так удобнее запускать контейнеры; для нашего сценария рекомендуем "да"). После этого выйдите (`exit`) и зайдите по SSH заново, чтобы группа применилась. Проверка: `docker run --rm hello-world`.

Откат: `sudo apt-get remove docker-ce docker-ce-cli containerd.io docker-compose-plugin`.

## Шаг 6. Swap и автообновления

```
sudo bash 40-swap-and-updates.sh
```

Создаст 1 ГБ swap и включит автоматические обновления безопасности. Автоматической перезагрузки нет: если скрипт напишет, что нужна перезагрузка, выполните `sudo reboot` в удобное время (потом подождите минуту и зайдите заново).

## Шаг 7. Каталоги приложения

```
sudo bash 50-app-dirs.sh
```

Создаст `/opt/hayeren` с подкаталогами `data`, `backups`, `caddy` и шаблон `.env` (без секретов, права 600). Существующий `.env` скрипт никогда не перезаписывает.

## Шаг 8. Проверка HTTPS

```
sudo bash 60-https-check.sh
```

Скрипт определит IP, предложит подтвердить, запустит только Caddy и получит бесплатный сертификат на адрес вида `203-0-113-10.sslip.io` (IP через дефисы). Откройте `https://203-0-113-10.sslip.io/health` в браузере на Mac: должен быть замок и слово `ok`. Пришлите в чат адрес (он публичный) и результат. Если не получилось, скрипт покажет логи Caddy, пришлите их.

Остановить тест: `sudo bash 60-https-check.sh down`. Это временная заглушка: когда появится бэкенд, мы дадим новый Caddyfile и полный docker-compose, а тестовый контейнер остановим.

Не запускайте `up` много раз подряд: у Let's Encrypt есть лимиты выпуска сертификатов.

## Шаг 9. Бот в Telegram и токен

Сначала мы согласуем с вами, когда это делать (токен нужен, когда будет готов бэкенд); бота можно создать заранее.

1. В Telegram откройте @BotFather (официальный бот с галочкой), отправьте `/newbot`.
2. Введите отображаемое имя (например, "Hayeren") и username, заканчивающийся на `bot` (например, `hayeren_app_bot`). Имя публичное, менять неудобно.
3. BotFather пришлёт токен вида `123456789:AAH...`. Это пароль от бота. Не пересылайте его никому, не вставляйте в чат с нами, не коммитьте. Сохраните в менеджере паролей.
4. На сервере (под deploy):

```
sudo bash ~/hayeren-app/server/ops/55-set-bot-token.sh
```

Скрипт попросит токен (ввод скрыт, на экране ничего не появляется) и username бота, запишет в `/opt/hayeren/.env` с правами 600. Токен нигде не печатается.
5. Нам пришлите только username бота (он публичный).
6. Если токен случайно попал куда-то лишнее: в @BotFather `/revoke`, затем повторите пункт 4 с новым токеном.

## Что делать, если потеряли доступ

1. Веб-консоль Vultr: my.vultr.com, ваш сервер, значок "View Console" (экран) вверху. Это вход как "физический" монитор, он работает без SSH и фаервола.
2. В консоли войдите как `deploy` (пароль, который вы задавали) или как root (если пароль root из панели ещё действует; при запрете root по SSH консоль всё равно позволяет войти локально).
3. Если не пускает SSH из-за настроек: `sudo bash ~/hayeren-app/server/ops/10-user-and-ssh.sh rollback` (или, как root, удалить файл `/etc/ssh/sshd_config.d/00-hayeren.conf` и выполнить `systemctl reload ssh`).
4. Если фаервол закрыл доступ: `sudo ufw disable`.
5. Крайний случай: в панели Vultr "Reinstall"/переустановка сервера (данные на нём пропадут), поэтому до появления бэкенда это безопасно, после - только после бэкапа.
6. Забыли парольную фразу ключа: создайте новый ключ (шаг 0 с другим именем файла) и добавьте его через консоль Vultr в `/home/deploy/.ssh/authorized_keys`.

Если при входе пишет `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED`, это может быть переустановка сервера. Если вы её делали, удалите старую запись: `ssh-keygen -R IP`. Если не делали, не входите и сообщите нам.
