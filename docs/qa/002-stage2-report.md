## 4. Баги

### BUG-1 (major): длинное армянское слово не помещается на карточке на 320–360 px
- **Шаги.** Открыть приложение при ширине 360 px (или 320). Добавить своё слово `անհամապատասխանություն` (21 буква, реальное слово «несоответствие», лимит `hy` = 60). Запустить сессию по набору.
- **Ожидаемо.** Слово целиком в карточке, без горизонтальной прокрутки страницы.
- **Фактически.** `HeroWord` уменьшает кегль до минимума 24 px, но слово всё равно шире карточки: `scrollWidth` страницы 389 px при ширине окна 360 (на 320 тоже), слово обрезается/уезжает за край, появляется горизонтальная прокрутка. Порог: при 360 px переполнение начинается с 19 букв, при 320 px раньше (с 17). Встроенные слова не затронуты (максимум 16 букв). Транслитерация (до 80 символов) и перевод без пробелов на карточке переполняют ширину так же (перевод из 38 символов без пробелов даёт 426 px).
- **Серьёзность: major** (основной экран обучения, целевые размеры 320/360, реальные слова из списка учителя). Предложение: минимум кегля ниже 24 px для очень длинных слов, либо `overflow-wrap: anywhere` для `translit` и `ru`, либо мягкий перенос слова.
- **Регрессия:** `e2e/qaStage2.spec.ts`, «BUG-1» (`test.fail`).

### BUG-2 (major): неиспользуемое название набора по умолчанию блокирует сохранение импорта
- **Шаги.** У пользователя уже есть набор «Набор от 19.10» (сегодняшнее число; например, создан вставкой утром). Импорт из файла `set;hy;ru` с колонкой «Набор» (все строки с названиями, например «Урок 5»). «Далее» → предпросмотр → «Сохранить 2 слова».
- **Ожидаемо.** Слова сохраняются в набор «Урок 5»: название по умолчанию нигде не используется (все строки с названием набора).
- **Фактически.** Под полем «Название нового набора» ошибка «Набор с таким названием уже есть», сохранение не происходит, пользователь не понимает, при чём тут это поле (в предпросмотре оно показывается как «Набор для строк без названия набора», строк без набора нет). Причина: `Preview.save` проверяет название нового набора по умолчанию независимо от того, нужен ли он. Обход: переименовать поле или выбрать существующий набор. Затрагивает основной сценарий критериев 102–105 (загрузка файла «с наборами» в приложение, где сегодня уже что-то добавляли).
- **Серьёзность: major.** Предложение: проверять название по умолчанию только если есть строки, которые попадут в него; либо не показывать поле, если таких строк нет.
- **Регрессия:** `e2e/qaStage2.spec.ts`, «BUG-2» (`test.fail`).
- Родственное наблюдение O-1: при повторной вставке в тот же день название по умолчанию тоже совпадёт с уже существующим набором, и первое «Сохранить» всегда даёт ошибку. Поведение по критерию 40 корректно, но неудобно.

### BUG-3 (minor): испорченный процент-код в адресе даёт белый экран
- **Шаги.** Открыть `#/sets/%E0%A4%A` (также `#/sets/s1/words/%`, `#/session/topic/%`, `#/session/set/%E0%A4%A`).
- **Ожидаемо.** Переход на главную, как для неизвестных маршрутов (`#/add/zzz`, `#/sets/nonexistent` ведут на главную).
- **Фактически.** Необработанное исключение `URIError: URI malformed` в `decodeURIComponent`, React размонтирует дерево, экран пустой; остаётся пустым после перезагрузки, пока в адресе то же значение.
- **Серьёзность: minor** (нужен вручную испорченный адрес; частично код этапа 1).
- **Регрессия:** «BUG-3» (`test.fail`).

### BUG-4 (minor): «Показаны первые 3 строк из 3»
- **Шаги.** Загрузить CSV из 1–4 строк (с заголовком) → экран «Что в колонках».
- **Ожидаемо.** Склонение по правилу из дизайна 1.4: «первые 1 строка / 3 строки / 5 строк» (в `plural.ts` есть `rowsWord`, не используется здесь).
- **Фактически.** «Показаны первые 3 строк из 3», «первые 1 строк из 1», «первые 2 строк из 2».
- **Регрессия:** «BUG-4» (`test.fail`).

### BUG-5 (minor): длинное название набора без пробелов вызывает горизонтальную прокрутку
- **Шаги.** Набор «Домашнее_задание_по_армянскому» (30 знаков без пробелов; допустимо до 50), ширина 320 px, экран набора.
- **Ожидаемо.** Заголовок переносится или обрезается с многоточием.
- **Фактически.** `h1` в верхней панели выходит за ширину: `scrollWidth` 437 px при 320; при 50 знаках — 848 px (и 602 px на форме правки, где в панели, видимо, то же). На главной и в списках название переносится нормально. Названия с обычными пробелами (как «Урок 5. Очень длинное…») не затронуты.
- **Серьёзность: minor.**
- **Регрессия:** «BUG-5» (`test.fail`).

### BUG-6 (minor): тост «Слово добавлено…» заходит на верх кнопки «Сохранить»
- **Шаги.** Форма «Добавить слово» (360×640, 320×568, 390×844) → сохранить слово.
- **Ожидаемо.** Тост выше нижней панели (как исправлено в BUG-1 этапа 1).
- **Фактически.** Тост (`pointer-events: none`, нажатия проходят) визуально закрывает верхние ~20 px кнопки «Сохранить» (тост 488–532, кнопка с 512 при 360×640). Текст кнопки виден.
- **Серьёзность: minor** (визуальный).
- **Регрессия:** «BUG-6» (`test.fail`).

### BUG-7 (minor): подсказка «Будет: …» для недопустимого армянского слова
- **Шаги.** Форма: «Армянское слово» = `բարեv` (латинская `v`), «Транслитерация» пусто.
- **Ожидаемо.** Подсказка не вводит в заблуждение: слово невалидно (после «Сохранить» будет ошибка).
- **Фактически.** «Оставьте пустым — создадим автоматически. Будет: bare, авто» (латинская буква молча теряется).
- **Серьёзность: minor.**
- **Регрессия:** «BUG-7» (`test.fail`).

### BUG-8 (minor): невидимые символы (ZWSP, LRM, мягкий перенос) в армянском слове
- **Шаги.** Вставить `բար​և — привет` (так бывает при копировании из мессенджеров и сайтов).
- **Ожидаемо.** Невидимый символ отбрасывается (или хотя бы ошибка называет его).
- **Фактически.** Ошибка «В армянском слове есть латинские или русские буквы: ​. Часто это похожие буквы…» — список символов выглядит пустым, пользователь не может найти причину.
- **Серьёзность: minor.**
- **Регрессия:** `src/domain/qaStage2.test.ts` «BUG-8» (`it.fails`), `e2e/qaStage2.spec.ts` «BUG-8» (`test.fail`).

### BUG-9 (minor): неверный разделитель CSV при одинаковом числе запятых в каждой строке без заголовка
- **Шаги.** Файл без заголовков, `;`-разделитель (как сохраняет русский Excel, запятые внутри ячеек не экранируются): `հաց, նկանակ;хлеб, булка` и `ջուր, ըմպելիք;вода, напиток`.
- **Ожидаемо.** `;` (2 колонки).
- **Фактически.** Выбирается `,` (3 колонки, «согласованное» число колонок побеждает), данные разъезжаются по колонкам, переключить разделитель вручную нельзя. Аналогично: TSV, где в каждой строке по одной `;` в ячейке, читается как `;` (при равенстве приоритет `;` над табуляцией). С заголовком `hy;ru` всё верно.
- **Серьёзность: minor.** Предложение: при равных очках предпочитать разделитель, встречающийся вне кавычек в первой строке чаще среди «основных» (`;`, табуляция), либо дать выбор разделителя на S14.
- **Регрессия:** unit «BUG-9» (`it.fails`).

### BUG-10 (minor): непарная кавычка в CSV молча склеивает остаток файла
- **Шаги.** CSV `hy;ru` / `բարև;"привет` / `հաց;хлеб` / `ջուր;вода`.
- **Ожидаемо.** Предупреждение о повреждённой кавычке или хотя бы разбор по строкам.
- **Фактически.** Файл читается как 2 строки: вторая содержит `привет հաց;хлеб ջուր;вода`; на предпросмотре одно «слово» с длинным переводом, остальные строки пропали без сообщения.
- **Серьёзность: minor** (файл некорректен по RFC 4180; спецификация это не определяет).
- **Регрессия:** unit «BUG-10» (`it.fails`).

### BUG-11 (minor, продуктовая рекомендация): `;` в переводе даёт абсурдную ошибку
- **Шаги.** Вставить `բարև — привет; здравствуйте` (синонимы через `;` — типичная запись учителя).
- **Ожидаемо.** Понятная причина.
- **Фактически.** По приоритету критерия 60 строка делится по `;`, «Армянским словом» становится `բարև — привет`, причина: «В армянском слове есть латинские или русские буквы: —, п, р, и, в, е, т. Часто это похожие буквы…». Поведение соответствует тексту критерия 60, но выглядит как баг. Предложение к контролёру: либо уточнить правило (разделитель `;` — только если нет тире), либо специальное сообщение «В строке есть и «;», и тире».
- **Регрессия:** unit «BUG-11» (`it.fails`).

### Ожидаемые баги (решения контролёра, ещё не сделаны)

### BUG-12 (major): на S14 пункт «Табуляция» не делит файл на колонки
- **Шаги.** Загрузить CSV/TSV (например, `հաց, նկանակ;хлеб⇥x` / `ջուր, ըմպելիք;вода⇥y`, ⇥ — табуляция) → экран «Что в колонках» → «Разделитель в файле» → «Табуляция».
- **Ожидаемо.** Файл делится по символу табуляции (2 колонки).
- **Фактически.** Файл превращается в **одну колонку** (в каждой строке весь текст, роль «Перевод» назначить некуда, «Далее» заблокирована с перечислением причин). Причина: в `app/src/screens/ImportColumns.tsx` `<option value="\t">` — в JSX-атрибуте обычной строки escape-последовательности не обрабатываются, поэтому значение — два символа `\` и `t`, а не табуляция; `rereadCsv(text, '\\t')` возвращает `delimiter: "\\t"`, строки не делятся. Подтверждено unit-вызовом `rereadCsv('a;b⇥c', '\\t')` → одна колонка, и в UI (`opt values ["auto",";",",","\\t"]`).
- **Серьёзность: major** — предложенный в интерфейсе пункт полностью не работает, а S14 введён как исправление BUG-9; обход есть (автоопределение обычно правильно определяет табуляцию), поэтому не blocker. Исправление: `<option value={'\t'}>`.
- **Регрессия:** `e2e/qaRound1.spec.ts`, «BUG-12» (`test.fail` — после исправления снять пометку).
