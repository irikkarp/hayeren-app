# Архитектура (этапы 1–3 MVP)

Код в `app/src`. Слои сверху вниз зависят только от нижних.

- `domain/` — чистые функции без React и хранилища, покрыты unit-тестами рядом (`*.test.ts`):
  - этап 1: даты (`dates`), SRS Лейтнера (`srs`), очередь сессий (`queue`), состояние сессии (`session`), подсчёты и серия (`stats`, `streak`), «Тема выучена» (`celebration`), маршруты (`router`), склонения и текст (`plural`, `text`);
  - этап 2 (свои слова): валидация полей и названия набора (`wordValidation`), автотранслитерация (`translit`), разбор вставки (`paste`), CSV (`csv`), сопоставление колонок и разбор строк файла (`importFile`), общие типы распознанных строк (`parsedRows`), дубликаты, целевые наборы и план сохранения с лимитами (`preview`), построение записей слов и наборов (`userWords`), UUID (`ids`);
  - «Видимый прогресс» (001 ред. 11, критерии 149–167): `progress` — `progressCounts(words, states)` (единственная функция подсчёта выучено box ≥ 4 / в изучении box 1–3 / не начато), строка прогресса, ширины сегментов и `aria-valuetext` бара, `nextReviewDate`, `formatReviewDate` (по календарным дням, устойчиво к переходу на летнее время), `noDueText` (один текст для плитки и кнопки при N = 0), `buildExplain` (пояснительный блок итога). `stats.learnedCount` и `topicProgress` делегируют ей; `session.sessionNewWords` считает слова, получившие состояние впервые в сессии (m), результат хранится в `SessionResult.newWords`;
  - этап 3 (экспорт): `exportCsv` — выбор наборов и слов, сборка CSV, защита от формул, имя файла, тексты (чистые функции).
- `platform/` — обращение к браузеру: `saveFile.ts` (сохранение файла, см. «Экспорт»).
- `data/` — встроенный словарь (`content.ts` импортирует `docs/content/words.json` через алиас `@content`), справочник алфавита и чтение файлов импорта (`readImportFile.ts`: `.csv` и `.xlsx`, лимиты и тексты ошибок).
- `storage/` — интерфейс `Repository` и две реализации: IndexedDB (`indexedDbRepository`, БД `hayeren` v1) и в памяти (`memoryRepository`: тесты и запасной вариант, когда IndexedDB недоступна, тогда `persistent = false` и показывается баннер B1). Обе реализации проходят один набор контрактных тестов.
- `store/` — `AppStore`: состояние в памяти + запись в Repository; `useAppState` для React.
- `ui/`, `screens/`, `styles/` — компоненты, экраны, CSS на токенах ui-kit. Роутинг: hash (`#/путь`), `router.ts`.
- `features.ts` — флаги этапов: `userSets` включён (этап 2), `backup` включён (этап 3, экспорт).

## Модель данных (под синхронизацию, фича 003)

У изменяемых записей есть `updatedAt` и `deletedAt` (мягкое удаление; `load()` отдаёт только живые, надгробия остаются в хранилище). Прогресс отдельно от слов.

| Хранилище      | Ключ                           | Содержимое                                                                                                       |
| -------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `settings`     | `settings`                     | режим `beginner`/`reader` (нет записи = первый запуск)                                                           |
| `progress`     | `wordId`                       | `box`, `dueDate`, `lastReviewed`, `correct`, `wrong`                                                             |
| `days`         | `date` (ГГГГ-ММ-ДД, локальная) | `answered` (серия), `newStarted`, `bonusNew` (дневной лимит новых)                                               |
| `celebrations` | `topicId`                      | `pending` / `celebrated` (экран «Тема выучена»)                                                                  |
| `userSets`     | UUID                           | `title`, `createdAt`                                                                                             |
| `userWords`    | `u-<UUID>` (индекс по `setId`) | `setId`, `hy`, `ru`, `translit`, `translitAuto`, `exampleHy`, `exampleRu`, `createdAt`                           |
| `meta`         | `key`                          | `lastBackupAt` → `{ key, value: мс }`: время последнего успешного экспорта (не сбрасывается «Сбросить прогресс») |

«Сбросить прогресс» мягко удаляет `progress`, `days`, `celebrations`; настройки и свои слова остаются.

### Свои слова

- Слово и его состояние SRS связаны по `id`; свои слова входят в каталог (`buildCatalog`) и участвуют в очередях, «Повторить (N)», статистике и серии наравне со встроенными. Порядок слов набора — по `createdAt`; при сохранении пачки `createdAt` растёт на 1 мс на запись, поэтому порядок строк (и порядок наборов из колонки «Набор») восстанавливается.
- Все изменения идут через `Repository.commitUserData({ sets, words, deleteProgress, now })`: одна транзакция на наборы, слова и удаление состояний. `AppStore` сначала пишет, потом обновляет состояние: при ошибке записи метод возвращает `false`, состояние не меняется, экран оставляет ввод пользователя.
- Удаление слова или набора: надгробия (`deletedAt`) для слов и наборов, надгробия для состояний SRS удалённых слов. Изменение слова (`editUserWord`) не трогает `id` и состояние SRS.
- Транслитерация: пустое поле → `transliterate(hy)` и `translitAuto = true`; введённая → ручная. В форме изменения у авто-слова поле транслитерации пустое (значит «авто»), поэтому при смене `hy` она пересчитывается, а ручная остаётся.
- Лимиты (100 наборов, 3000 слов) и правила названия набора проверяет `planSave` до записи, в операции «всё или ничего».

## Потоки добавления слов

Маршруты: `/add` (способ), `/add/paste`, `/add/word`, `/add/file`, `/add/file/columns`, `/add/preview`, `/sets/:id`, `/sets/:id/words/:wordId`; `?set=<id>` передаётся по всей цепочке `/add*`.

Незавершённый ввод живёт в `AppState.addFlow` (текст вставки, прочитанный файл, сопоставление колонок, результат разбора), пока пользователь не вышел из потока: вход на `/add` и успешное сохранение его сбрасывают, «Назад» не теряет данные.

Вставка: `parsePaste` → `ParseOutput` → экран предпросмотра. Файл: `readImportFile` (читает на устройстве) → `detectMapping` → экран колонок → `applyMapping` → `ParseOutput` → тот же экран предпросмотра. Предпросмотр строит строки через `buildPreviewItems` (целевой набор, дубликаты) заново при каждой смене выбора набора; сохранение — `planSave` → `AppStore.saveUserWords`.

### Формат файла импорта (совместим с будущим экспортом, критерии 92–95)

Колонки `set;hy;ru;translit;example_hy;example_ru` опознаются по заголовкам без настройки. CSV: UTF-8 с BOM или без (строгая проверка кодировки), разделитель `;` `,` или табуляция определяется по первым строкам, кавычки и переводы строк внутри значений по RFC 4180. Из значений вида `'-…`, `'=…`, `'+…`, `'@…` удаляется один апостроф (защита от формул, обратная сторона экспорта). Разделитель можно выбрать вручную на экране колонок (`rereadCsv` перечитывает исходный текст из `ImportedFile.csvText`); при равенстве колонок автоопределение предпочитает `;`. Непарная кавычка — ошибка файла с номером строки. Строки в ошибках нумеруются как в Excel (с учётом заголовка).

### Библиотека XLSX

`read-excel-file` (MIT), точка входа `read-excel-file/browser`. Подгружается динамическим `import()` только при выборе `.xlsx` (отдельный чанк около 52 КБ, 16 КБ в gzip), входит в precache сервис-воркера, поэтому работает офлайн. Основной бандл её не содержит.

## Даты

«Сегодня» = локальная дата устройства (`toDateKey`). `AppStore.refreshToday()` вызывается при возврате в приложение и в полночь.

## Экспорт (этап 3, критерии 88–109)

- `Repository.putLastBackup(at)` пишет дату в `meta`, `Snapshot.lastBackupAt` её отдаёт; `AppState.lastBackupAt` показывается в настройках как «Последняя копия: ДД.ММ.ГГГГ».
- `AppStore.exportWords(setId?)`: `buildExportFile` (чистая функция) собирает текст и имя; файл сразу передаётся `deps.saveFile` (по умолчанию `platform/saveFile`), и только после успеха обновляется дата. Результат: `ok` / `empty` / `cancelled` (закрыто меню «Поделиться») / `failed`. Метод вызывается прямо из обработчика нажатия до любых `await`: iOS требует жеста пользователя для меню «Поделиться».
- UI: `ui/useExport` (состояния `busy` «Готовим файл…» и `status` done/failed), `ui/ExportStatus` (результат прямо в потоке страницы рядом с кнопкой, не fixed-тост: успех «Файл сохранён. Прогресс в файл не входит.» на 10 с с «Закрыть», ошибка `role="alert"` до следующей удачной попытки или ухода с экрана), `ui/ExportButton`, `ui/StorageNote` (заметка и кнопка «Экспортировать»), раздел «Резервная копия» в `screens/Settings`, кнопка «Экспортировать набор» в `screens/SetScreen`. Обычные тосты (`ToastProvider`) закрываются при любой смене маршрута.
- Формат: BOM, `;`, CRLF, RFC 4180 (кавычки при `; , " CR LF`), заголовки `set;hy;ru;translit;example_hy;example_ru`; у слов с `translitAuto` ячейка `translit` пуста; значение, начинающееся (после возможных `'`) с `= + - @`, получает ведущий `'` (импорт убирает один: `unprotectFormula`). Порядок: наборы и слова по `createdAt`, пустые наборы пропускаются. Прогресс SRS не экспортируется.
- Способ сохранения файла (`platform/saveFile.ts`): везде `Blob` + `<a download>` (Chrome/Edge/Firefox, Safari macOS и iOS, PWA на Android). Исключение — установленное PWA на iOS (`display-mode: standalone` / `navigator.standalone`): там загрузка blob ненадёжна, поэтому при `navigator.canShare({ files })` открывается системное меню Web Share API с файлом `text/csv`; если пользователь его закрыл (`AbortError`) — тихо отменяем без обновления даты, при другой ошибке падаем на `<a download>`.
- Тесты: `domain/exportCsv.test.ts` (формат, защита от формул, имя файла, сквозной round-trip через всю цепочку импорта), `store/appStore.test.ts`, контракт `storage/repository.test.ts`; e2e `e2e/backup.spec.ts` (скачанный файл, round-trip через интерфейс, офлайн, Web Share, 320/360 px, тёмная тема, axe).
- Нормализация: импорт схлопывает любые пробельные символы (включая переводы строк) в один пробел (`normalizeText`), поэтому в сохранённых словах переводов строк нет; в CSV они экранируются корректно (проверено на уровне сериализатора и разбора).

## Как добавлять этапы

Фича 003 (синхронизация): записи уже имеют `updatedAt`/`deletedAt`; дата последней копии лежит в `meta` и синхронизироваться не должна.
